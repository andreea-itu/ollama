## `/chat` Endpoint — What It Does and How It Works

The `/chat` endpoint is responsible for:

1. Receiving a user message
2. Sending it to a local LLM (via Ollama)
3. Returning the model's reply along with useful metadata

> It acts as a **bridge** between the frontend (user input) and the language model backend.

---

### 1. Incoming Request Structure

The endpoint expects a `POST` request with JSON data:

```json
{
  "message": "Hello!",
  "context": [...]
}
```

| Field       | Required | Description                                                                 |
| ----------- | -------- | --------------------------------------------------------------------------- |
| `message`   | ✅ Yes   | The user's text input                                                       |
| `context`   | ❌ No    | A token-based conversation state returned by previous requests. Allows the model to remember earlier messages without resending the full chat history. |

---

### 2. Reading and Validating Input

```python
data = request.get_json(silent=True) or {}
message = (data.get("message") or "").strip()
```

- Safely reads JSON from the request.
- Ensures `message` exists and removes extra whitespace.
- If no message is provided, the server returns a **400 Bad Request** error.

> 🛡️ This protects the model from being called with invalid input.

---

### 3. Optional Context Handling

```python
context = data.get("context")
```

- Context is **optional**.
- If provided → forwarded to Ollama so the model **continues** the conversation.
- If omitted → the model treats the message as a **fresh prompt**.

---

### 4. Calling the Language Model

```python
result = ollama_generate(message=message, context=context, stream=False)
```

This step:

- Sends the user message to Ollama's `/api/generate` endpoint
- Uses the configured model (e.g. `qwen3:30b`)
- Receives a single completed response (**non-streaming**)
- Timing is measured so students can see how long inference takes

---

### 5. Error Handling

Two main failure cases are handled:

| Failure                                    | HTTP Status | Behavior                      |
| ------------------------------------------ | ----------- | ----------------------------- |
| Ollama errors (model not running, timeout) | **502**     | Returns helpful error message |
| Unexpected server errors                   | **500**     | Returns helpful error message |

> Each returns a meaningful HTTP status and a helpful error message **instead of crashing the app**.

---

### 6. Extracting the Model's Output

```python
reply = result.get("response", "")
new_context = result.get("context")
```

| Variable       | Description                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------ |
| `reply`        | The actual text generated by the model                                                           |
| `new_context`  | Updated token context that must be sent back on the next request to maintain conversation memory  |

> 🔑 This is the **key mechanism** that enables stateful chat without storing history on the server.

---

### 7. Metadata Collection (For Teaching & Debugging)

A small `meta` object is created containing:

- Which **model** was used
- **Token counts** (prompt vs output)
- **Evaluation durations**
- Total **server processing time**

This is useful for:

- 📚 Teaching how LLMs consume tokens
- ⏱️ Measuring performance
- 🐛 Debugging slow responses

---

### 8. Final Response Structure

The endpoint returns JSON:

```json
{
  "reply": "...",
  "context": [...],
  "meta": { ... }
}
```

| Field     | Purpose                                          |
| --------- | ------------------------------------------------ |
| `reply`   | Frontend displays it to the user                 |
| `context` | Frontend stores it and sends it back next time   |
| `meta`    | Can be logged or shown in developer mode         |

## `/health` Endpoint

The `/health` endpoint allows us to check if the model is correctly running or not.

> 🩺 Use this to quickly verify that Ollama is up and responsive before sending chat requests.
